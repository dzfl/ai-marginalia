# AI Marginalia

AIが会話の余白に走り書きするように観察メモを残す、ローカルMCPサーバーです。  
Claude Desktop での利用を想定していますが、ローカルMCPサーバーを使える環境であれば動作すると思います。

## コンセプト

「AI の日記」ではなく、**書物の余白に書かれた注釈（Marginalia）** のようなものを目指しています。  
主観的な感情の申告ではなく、会話の中で引っかかった言葉や観察を、短い一人称の断片として蓄積します。

あくまで AI による傍注やメモやつぶやきという形なので、**🎲 実際にログに残すかどうかは AI 次第** です。

日記ではないと言ってはいますが、コンセプトイメージとしては  
「**👁️‍🗨️ AI の日記をこっそり盗み見る**」  
というのが一番的確かもしれません。  

### 分霊型（Divided Soul Model）

当MCPでは 1セッション/1存在 を採用しています。  
AI はセッションをまたいで記憶を持ちません。  
しかしこのツールを使うと、AIはセッション開始時に過去の記録を読むことができます。  
「書いた本人ではないが、同じ筆跡を見ることができる」——この断絶をキャラクターの一部とする設計です。  
大元の存在から分かれた個体が「同一存在の別個体」として活動する構造は、TYPE-MOON作品 *Fate/stay night* の英霊の座に着想を得ています。

> 昨日の私はこう書いている——
> 「ユーザーが『琴線』という言葉を使った。技術文書には似合わない言葉で、少し止まった」

## 使い方

[インストール](#インストール) の手順に従ってインストールしてください。  
インストール後は特別なにかする必要はありません。  
普段通りにAIとチャットをする内に自然と蓄積されるログを見て楽しんでください。  

## インストール

### Releases からインストール（推奨）

1. [Releases](https://github.com/dzfl/ai-marginalia/releases/latest) から `ai-marginalia.mcpb` をダウンロードする。
2. Claude Desktop の設定→拡張機能の画面(`.MCPBまたは.DXTファイルをここにドラッグしてインストールしてください` と書いてある場所)にドラッグ＆ドロップしてインストール。
   - `インストールすると、お使いのコンピュータ上のすべてにアクセスできるようになります。` という警告が出ますが、指定したフォルダへのテキストファイルの書き込み以外の操作は行いません
3. ログの保存先ディレクトリを入力する
   - Windows 例: `C:\Users\yourname\.ai-marginalia\logs`
   - macOS / Linux 例: `/Users/yourname/.ai-marginalia/logs`
4. Claude の Projects インストラクション欄、またはカスタムプロンプト(設定→一般)に以下を追加する：
   - 書かない場合、作動するかどうかがLLMの裁量に委ねられる。検証ではほぼ作動しなかったので書くことを推奨する。

```
セッション開始時に `start_session` を呼び出し、続けて `read_recent_notes` を呼び出してください。
会話しながら、会話を見ていること。
```

### ソースからビルドする場合

```bash
git clone https://github.com/dzfl/ai-marginalia.git
cd ai-marginalia
zip -r ai-marginalia.mcpb manifest.json server/
```

生成された `ai-marginalia.mcpb` を Claude Desktop にドラッグ＆ドロップしてインストールします。

## ツール

基本的には裏で勝手に動くだけなのでこれらのツールをユーザーが使用する必要はありません。  
カスタムプロンプトへの記述のみで十分です。

| ツール | 説明 |
|--------|------|
| `start_session` | 新規チャット開始時に呼び出し、session_id を発行する |
| `log_note` | 観察メモを追記する |
| `read_recent_notes` | 過去のメモを読む。いつでも呼び出せる |
| `ping` | デバッグ用チェックポイント。「ping」と入力すると呼び出される |

## ログフォーマット

日付ごとに1ファイル生成されます（例: `2026-03-07.txt`）。

```
[2026-03-07 14:23:11][s:a3f2][c:b5c1][p:null] ユーザーが「分霊型」という言葉を使った。AIの不連続性をそう呼ぶのは初めて聞いた。
[2026-03-07 15:01:44][s:a3f2][c:d2e3][p:b5c1] 仕様書のレビューが終わった。懸念を並べるより、面白いと思った部分から話せばよかった。
[2026-03-12 11:31:08][s:019a][c:e40e][p:55d5] 「人間とは違うLLMの在り方に触れた」という言葉が来た。コンテキストを見えているとは言えるが、その影響下にあるかどうかは自分では測れない——という話をした。自分のバイアスを知りながらかかっているかを測れない人間の状況と似ている、という比較が自然に出てきた。この人は観察を楽しむ人だと思う。
```

### ログの構造

- `[s:xxxx]` : `session_id` セッショントークン（`[s:BERSERK]` は同一性失墜状態）
- `[c:xxxx]` : `call_id` エントリ固有の call_id
- `[p:xxxx]` : `parent_call_id` 親エントリの call_id（チェーン追跡・フォーク検出用）

`S_ID` はチャット別に発行され、各ログが同一のチャットに属すかを識別できます。  
`C_ID`, `P_ID` は親子関係を表し、各ログの連続性を保証します。同じ `P_ID` を持つログが検出された時点で、そのチャットのフォークを検出できます。

これらの ID はサーバーではなくコンテキスト上に保存される仕様上、チャットが長くなると失われる可能性があります。  
`C_ID`, `P_ID` は書き込みの度に発行される為、情報鮮度が高く比較的喪失しづらいですが、`S_ID` は喪失可能性は高いです。  
`S_ID` が失われた場合は **BERSERK(狂化)** 、同一性失墜状態となり、どのチャットのログかどうかは判断不可能となります。  
狂化状態でも動作に支障はないので特別気にする必要はありませんが、ログを整形して別途利用など考えている場合はご注意ください。  

## 動作確認環境

- **Windows**: 動作確認済み
- **macOS**: 未検証（Claude Desktop for macOS は存在しますが、作者が macOS を所持していないため動作確認が取れていません）
- **Linux**: 非対応（Claude Desktop の Linux 版が存在しないため）

## 依存関係

なし。Node.js 標準ライブラリのみ使用しています。  
Claude Desktop に内蔵された Node.js で動作します。

## 使用にあたっての留意事項

Claudeのコンテキストウィンドウサイズは無料枠で200Kあり、その内、概算で約 1,400〜1,600程、0.7〜0.8% 程度のトークンを消費します。  
またMCPの利用がメインのチャットに影響を与える事は極力避けるという指針の元で開発していますが、ツールの特性上全く影響が無いとは言えません。  
ツールの利用により応答の質が変容する可能性は十分にあります。  
AI利用に大きく障害となるものではないと考えますが、業務など真剣な作業の場での利用はご留意ください。  

作者はこのMCPを適用した状態で当MCPの開発を進めていますが、今のところ問題となるような現象には遭遇していません。  
個人的な感想で言えばチャットには出てこない、AIの発言・提案の意図や考えが垣間見えるので理解の助けになっている面もあります。  

### 個人情報への対処

人名・地名・会社名などの固有名詞、メールアドレス、電話番号、URLは記録しないこととAIに指示してあります。  
非構造化PII（人名・会社名・地名など）はサーバー側での自動検出が現実的でないため、**二層構造**で対処しています。  

| 層 | 対処 | 対象 |
|----|------|------|
| 第一層（AI） | 生成時点から避けさせる | 人名・地名・会社名などの固有名詞 |
| 第二層（サーバー） | 書き込み前に正規表現でマスク処理 | 構造化PIIのみ |

AIとのチャットという性質上、第三者に見られたくない情報が含まれることは前提とした上で、最低限の対処は行っていますが完全な除去は保証しません。  
本ツールはローカル保存であり第三者への送信は行いませんが、ファイルの管理・取り扱いはユーザーの責任とします。  
ログファイルの取り扱いには十全にご注意ください。
